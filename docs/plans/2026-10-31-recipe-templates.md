# Recipe format

Date: 2026-10-31
Status: in progress — work item 1 done; next is the human-run migration
Scope: `sloppr/` backend. The Angular client is regenerated by a human after the contract
changes.

## Goal

Every recipe has the same shape. Dishes that need parts (sauce, marinade, topping) can
group them without changing that shape. Recipes are delivered as markdown files.

## Recipe shape

- Info: name, description, servings, prep minutes, cook minutes, difficulty (1–3),
  optional notes.
- Ingredients: order, quantity (optional), unit (optional), name, group (optional),
  note (optional).
- Steps: order, instruction, group (optional).

`Group` is the only flexibility. Blank means the main recipe. "Sauce" or "Marinade"
groups the matching ingredients and steps. Plain recipes look like one list; grouped
recipes look like the same list split by label.

## Storage

- `Recipes` — recipe info.
- `RecipeIngredients` — ordered ingredient rows.
- `RecipeSteps` — ordered step rows.
- `RecipeFormats` — append-only format versions.

All four are DbSets, so the table names are plural.

## Where the format lives

Formats are stored in the `RecipeFormats` table as append-only rows: key, version, rules
(JSON), current flag, created date. Each recipe saves the key and version it used, with a
foreign key to that row, so a format cannot be deleted while recipes reference it.

- New recipes use the current row. Old recipes keep their row and rules.
- Publishing a change inserts a new row; it never edits an old one.
- The rules JSON is a historical snapshot; the app does not interpret it.
- A small code validator enforces the current format.
- A recipe with an unknown key or version is rejected.
- Published rows are never edited or deleted while recipes use them.
- Version 1 is seeded by the migration from a code constant.

Bad AI output returns `502`. Bad manual input returns `400`.

Markdown output uses one built-in layout. User-customized layouts are not part of this
plan.

## Not included

Multi-day recipes, equipment lists, nutrition, user-customized layouts, the WYSIWYG
editor, and editing formats through the API or UI. Version 1 is seeded; new versions are
added deliberately. Add a new format version later if a real recipe cannot fit.
