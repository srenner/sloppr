# Recipe format reset: remove the format layer

Date: 2026-11-02
Status: code complete — format layer removed and generation verified. Pending: apply the
difficulty migration and regenerate the client.
Scope: `sloppr/` backend, request files, and generated client contract. No template or
replacement renderer in this phase.

## Goal

Delete the existing recipe format machinery — DB format rows, rules JSON, validator, and
markdown renderer — so the recipe data model stands on its own. This is a reset, not a
migration to a new format. The markdown template is a separate follow-up phase.

## Why reset first

The current format has three overlapping sources: `RecipeFormats.Rules` (JSON), the code
rules/validator, and the hardcoded markdown renderer. Removing them first avoids carrying
old assumptions into the template design and makes the next phase a clean add.

## Progress

- Removed the format files, format columns, `RecipeFormats` table, validator, and markdown
  endpoint.
- Split the SQLite work into `RemoveRecipeFormat` (columns/FK) and
  `RemoveRecipeFormatsTable` (table drop). Both are applied.
- `Difficulty` is optional end-to-end (`int?`, nullable column) via
  `MakeRecipeDifficultyOptional`; the migration is generated but not yet applied.
- AI generation uses a `RecipeGenerationResponse` JSON schema and returns a valid
  `Location` header.
- Verified on a database copy: generation returns `201`, the recipe persists, and reads
  back with optional difficulty.

## Behavior after removal

- `POST` / `PUT /api/Recipes` store recipes without a format stamp or format validation.
  The meal-idea existence check stays.
- `POST /api/AiInference/recipes/{mealIdeaId}` still generates and saves a recipe, but no
  longer requires a format row.
- `GET /api/Recipes/{id}/markdown` no longer exists.
- `RecipeDTO` no longer has `formatKey` / `formatVersion`.
- `RecipeFormats` is dropped from the database.

This intentionally leaves recipes without field validation and without markdown output.
Do not fill those gaps in this phase.

## Database

Migrations are generated and follow the SQLite-safe split:

- `20261102141433_RemoveRecipeFormat` — drops the `Recipes.FormatKey` /
  `FormatVersion` index, foreign key, and columns.
- `20261102142000_RemoveRecipeFormatsTable` — drops `RecipeFormats` after the rebuild.
- `20261103002654_MakeRecipeDifficultyOptional` — makes `Recipes.Difficulty` nullable.

The first two are applied. Apply the remaining one with:

```bash
cd sloppr
dotnet ef database update
```

Keep the old `RecipeFormat` migration as history.
